# 使用与实现说明

本文回答两个问题：**卸载清理功能具体怎么实现的**，以及**界面上每个按钮是干什么的**。

---

## 第一部分：卸载清理是怎么实现的

### 1.1 核心概念：什么叫「残留」

工具不试图自己卸载程序。它把「让一个 Agent 从这台机器上消失」拆成两段：

```
① 程序本体  →  交给官方卸载器（唯一不可逆的一步）
② 卸载后剩下的东西  →  由本工具清理，这一步叫「残留清理」
```

「残留」指卸载器通常不会删的东西。本机实测的类别：

| 类别 | 例子 | 为什么卸载器不管 |
|---|---|---|
| 用户数据 | `~/.dsh`（745 MB）、`~/.workbuddy`（704 MB） | 设计上保留，以便重装后配置还在 |
| 可再生缓存 | `transport-profile` 里的 184 MB 组件缓存 | 卸载器不遍历用户目录 |
| 日志 | `~/.workbuddy/logs` | 同上 |
| 空壳目录 | `~/WorkBuddy`、`E:\WorkBuddyStorage`（0 文件） | 卸载器只删它自己创建的文件 |
| 密钥凭据 | `~/.workbuddy-key-fallback/connector-keys/*.key` | 属于用户数据 |
| 机器级对象 | 防火墙规则、`HKLM` 键、`ProgramData` 快捷方式 | 普通权限删不掉 |

### 1.2 模块分工

```
core/wininteg.py    读取 Windows 侧事实：注册表卸载项、厂商键、防火墙规则、
                    快捷方式（含目标是否存在）、服务、计划任务、自启动
core/residue.py     把上述事实 + 文件系统扫描合并成一份「该 Agent 还剩什么」
core/ownership.py   给每个路径判归属与风险，输出 safe / review / never
core/uninstall.py   5 阶段向导，把上面几件事串成流程
core/cleaner.py     真正动手删残留（写权限只在这里）
core/elevate.py     需要管理员的那几项，合并成一次 UAC 授权执行
core/quarantine.py  隔离区保留策略（7 天 / 2 GB / 1 小时保护期）
core/executor.py    删「会话」的写入路径（与残留清理是两条独立路径）
```

### 1.3 最关键的一步：归属分级

干净与否取决于**判得准不准**，而不是删得多不多。`ownership.py` 按三轴判定：

- **owner**：属于哪个 Agent
- **confidence**：`exact`（适配器声明根 / 注册表推导）/ `heuristic`（命名规律）/ `unknown`
- **category**：缓存 / 日志 / 凭据 / 会话 / 配置 / 插件 / 二进制 / 用户数据 / 共享 / 源码仓库

三轴合成三个处置档：

| 档位 | 判定条件 | 界面默认 |
|---|---|---|
| `safe` 可安全清理 | 明确属于该 Agent 且可再生（纯缓存、日志、空目录） | 已勾选 |
| `review` 需人工确认 | 属于该 Agent 但可能有用（会话、配置、插件、凭据） | 未勾选 |
| `never` 禁止删除 | 用户数据、共享资源、源码仓库、归属不明 | 只读，展示原因 |

**每一条判定都带 `evidence` 字符串**，界面上直接显示，你可以核对它凭什么这么判。

几个真实的判定细节（都是为了不误删）：

- 本机存在 `E:\workbuddyapi-main`——你自己的 git 仓库，里面恰好有个 `.codebuddy` 目录。命中 `.git`/`package.json` 等特征即判 `never`。**任何按关键词扫盘的工具都会把它删掉。**
- `%APPDATA%\Microsoft\Windows\Start Menu\...` 同时含 "Microsoft" 和 "Windows"，共享容器规则若扫全路径就会把**所有快捷方式**判成 `never`。所以该规则只看驱动符下前两层。
- `state.vscdb` 是 VS Code 状态库，不是缓存；数据库及其预写日志一律判 user_data。
- 空目录不含任何文件 → 一律 `safe`（删了不可能丢数据）。
- 凭据识别要求「文件名像」**且**「扩展名不是源码/文档」**且**（必要时）「内容像密钥」，否则一个自带运行时能报出 150 个假密钥。

**递归下钻**：`~/.dsh` 整体是 `never`（它是数据根），但内部 472 MB 缓存会单独列出——`never` 的父目录不掩盖其下的可操作项。

### 1.4 5 阶段流程

| 阶段 | 做什么 | 代码 | API |
|---|---|---|---|
| ① 预检 | 进程是否在跑？有保留标记？注册表里有卸载器吗？会剩什么？哪些要管理员？列出全部密钥文件 | `uninstall.preflight()` | `GET /api/uninstall/preflight` |
| ② 调用官方卸载器 | 读注册表 `QuietUninstallString`，**唯一不可逆的一步** | `cleaner.run_uninstaller()` | `POST /api/uninstall/run`（需 `confirm`） |
| ③ 卸载后验证 | 重新扫描，**不信卸载器返回的「成功」**，列出真正剩下什么 | `uninstall.verify()` | `GET /api/uninstall/verify` |
| ④ 残留分级清理 | 按档位删除，支持预演 | `uninstall.execute_cleanup()` → `cleaner.CleanupExecutor` | `POST /api/cleanup` |
| ⑤ 报告 | 操作记录 + 可还原项 | `uninstall.report()` | `GET /api/uninstall/report` |

### 1.5 删除时的四道保障

任一环节失败即整体回滚：

```
校验目标 → 备份 → 移入隔离区 → 改数据库/注册表 → 回读验证 → 写日志
```

1. **隔离区**：文件与目录移入 `_data/quarantine/<op-id>/`，可按 op-id 还原。删注册表键前先 `reg export`，删防火墙规则前先导出 JSON。
2. **操作日志**：`_data/operations.jsonl`，每步动作、结果、错误都记。**这是唯一的事故追溯依据**，工具不清理它。
3. **会计恒等式**：清理结果自带 `accounting` 字段，保证 `选中 = 已执行 + 已报告`。任何既没被执行也没出现在 `reported` 里的项目会被测试判为失败。（这条是因为「快捷方式曾被静默丢弃」才加的。）
4. **运行中门禁**：Agent 进程在跑时只允许预演，真正执行会被拒绝——删除正在使用的缓存/配置会损坏它。

### 1.6 提权是怎么做的

需要管理员的三类：`HKLM` 注册表键、防火墙规则、`ProgramData` 快捷方式。

工具**不静默提权**，也不逐条弹窗，而是：

1. 把该 Agent 的全部提权项收集成一份清单（`elevate.privileged_actions`）
2. 生成**一个** PowerShell 脚本（`elevate.build_script`），脚本里每项都是：检查目标是否存在 → 备份到隔离区 → 删除 → 回读确认
3. 界面可展开查看这份脚本的**完整内容**
4. 你点确认后，才 `Start-Process -Verb RunAs` 弹出**一次** UAC
5. 脚本把逐项结果写成 JSON，父进程读回并记入日志

脚本以 UTF-8 带 BOM 的字节写出；目标名含换行/NUL 一律**拒绝处理**（fail closed）——因为注释或字符串里的换行可能逃逸成以管理员执行的命令。

## 第二部分：每个按钮是干什么的

### 2.1 总览

| 按钮 | 作用 | 调用的接口 |
|---|---|---|
| **复制** | 复制该 Agent 的完整存储路径（可能多个）到剪贴板；失败时自动选中文本并提示按 Ctrl+C | 无（读已加载的报告） |
| **查看会话** | 跳到「会话」页，并**自动筛选到该 Agent** | 无（切页 + 设筛选） |

卡片上的三行分别是会话数、占用空间（整棵目录树）、文件数。路径下方标注是否「运行中」。

### 2.2 会话

| 控件 | 作用 |
|---|---|
| 搜索框 | 按标题、路径、会话 ID 过滤（不搜正文，正文搜索在专门那页） |
| Agent 下拉 | 按 Agent 筛选 |
| 排序下拉 | 按体积 / 时间 / 标题 / 价值排序 |
| 只看残留 | 只显示幽灵条目（索引在、正文没了）和孤儿会话（正文在、索引没引用） |
| **重新扫描** | 重新读取所有 Agent 的会话并刷新价值评分 |
| 行内 **查看** | 打开只读预览，看会话正文（判断是否真该删） |
| 行内 **保留** | 打上保留标记。**已标记的会话拒绝删除**，需显式勾选「忽略保留标记」才能绕过 |
| 行内 **导出** | 导出为 Markdown / JSON / 纯文本到 `_data/exports/` |
| 行内 **删除…** | 打开删除计划（列出每个具体动作、预计释放多少、是否可还原），确认后才删 |
| **删除选中项…** | 批量删除。**先出预演**：列出将删多少、哪些会被安全检查阻止及原因；确认按钮显示实际可删数量 |
| **取消选择** | 清空勾选 |

预览弹窗里还有两个快捷操作：**导出…**、**删除这个会话…**。

### 2.3 内容搜索

| 控件 | 作用 |
|---|---|
| 搜索框 + **搜索** | 在会话**正文**里全文检索（用户消息、助手回复、思考、工具调用与结果），不受预览截断限制。跨会话命中，非本机会话标为「不可搜索」 |
| 正则 / 区分大小写 | 匹配方式开关 |
| Agent 下拉 | 限定范围 |
| 结果行 **查看会话** / **保留** / **删除…** | 与「会话」页同义 |

数据库类 Agent（Copilot）走 FTS 索引；本工具自己维护文件类 Agent 的正文索引。

### 2.4 用量

按会话显示 token（输入 / 输出 / 缓存读 / 合计）与费用。**记录不到就显示「未记录」，不写 0** —— 0 会被误读成「没用量」。行内 **查看** / **删除…** 同义。

### 2.5 清理建议

| 控件 | 作用 |
|---|---|
| 规则复选框 | 7 条规则：空会话 / 幽灵条目 / 孤儿会话 / 长期未用 / 零碎小会话 / 体积过大 / 从未打开 |
| 「超过 N 天」输入 | 给「长期未用」等带时间参数的规则用 |
| **应用规则** | 重新计算并列出符合条件的会话。**只筛选，不执行** |
| **全选** / **取消选择** | 批量勾选 |
| **批量删除选中项…** | 与「会话」页的批量删除同一条路径（`/api/batch-delete`），同样先预演 |
| 行内 **查看** / **删除…** | 同义 |

### 2.6 卸载清理

顶部表格是各 Agent 的残留概览（可安全回收 / 需人工确认 / 禁止删除 / 密钥数量），每行一个 **查看残留**。

点进去后是 5 阶段，按钮按阶段分布：

**预检阶段**
| 按钮 | 作用 |
|---|---|
| **重新预检** | 重跑预检（`/api/uninstall/preflight`） |
| **下一步：卸载后验证** | 跳到阶段③ |
| **查看清理方案** | 跳到阶段④（生成残留分级清单） |

**卸载器面板**（阶段②，仅当注册表里找到卸载条目时出现）
| 按钮 | 作用 |
|---|---|
| **执行卸载** | 调用该产品**自己的**卸载器。必须先勾选确认框，再确认一次。静默模式的卸载器会等待其结束；无静默参数的会弹出图形界面并立即返回，需要你手动点完。执行完可直接进入阶段③ |

这是整个流程里**唯一不可逆**的一步。工具不代按「下一步」，也不重试。

**提权面板**（若该 Agent 有需管理员的项）
| 按钮 | 作用 |
|---|---|
| **查看将运行的脚本** | 展开显示将以管理员身份运行的**完整 PowerShell 内容**（复用已取回的方案，不重新扫描） |
| **以管理员身份执行 N 项** | 弹**一次** UAC，合并执行全部提权项；每项先备份后删除并回读确认 |

**验证阶段**
| 按钮 | 作用 |
|---|---|
| **下一步：清理残留** | 跳到阶段④ |
| **返回预检** | 回到阶段① |

**清理阶段**（三组：可安全清理 / 需人工确认 / 禁止删除）
| 按钮 | 作用 |
|---|---|
| **预演** | 只报告将移除多少、拒绝多少，**不改动任何文件** |
| **清理选中项** | 真正执行，默认进隔离区可还原 |

两个复选框：**永久删除**（不进隔离区，无法还原）、**包含数据根目录**（连 `~/.dsh` 这类数据根一起删，不可逆，需显式勾）。

**执行后**
| 按钮 | 作用 |
|---|---|
| **重新验证残留** | 重跑验证，确认还剩什么 |

### 2.7 操作记录

每次删除与清理的完整记录。**还原** 按 op-id 把隔离区里的内容放回原处（数据库行与索引条目从日志回填，所以不会覆盖后续的无关改动）。

### 2.8 弹窗里的通用按钮

| 按钮 | 作用 |
|---|---|
| **取消 / 关闭** | 关掉弹窗，不做任何事 |
| **确认删除** | 提交删除。会带上计划指纹，若期间内容变了则拒绝执行并提示重新查看 |
| **重新查看计划** | 指纹不匹配时用：重新生成计划再确认 |
| **完成** | 删除成功后关闭弹窗并刷新列表 |
| **还原**（操作记录） | 见上 |

### 2.9 几个容易误解的复选框

| 复选框 | 含义 |
|---|---|
| **永久删除（不进隔离区，无法还原）** | 不保留备份。默认**不勾**，数据进隔离区可还原 |
| **忽略保留标记（仅本次）** | 绕过「保留」保护。只对本次生效，**不会取消标记本身** |
| **同时删除这些附件** | 删除该会话引用的、且未被其他会话引用的附件。默认不勾（判断基于文本匹配，属保守策略） |
| **包含数据根目录** | 连 Agent 的数据根一起删，不可逆 |

## 第三部分：与 CLI 的对应关系

界面上的每个操作都有对应命令，便于脚本化：

```powershell
python cli.py capabilities                 # 能清理什么、不能清理什么
python cli.py scan                         # 各 Agent 会话与占用
python cli.py sessions --agent dsh         # 列出会话
python cli.py plan --agent dsh --sid <id>  # 审阅删除计划（只读）
python cli.py delete --agent dsh --sid <id> --yes
python cli.py residue --agent workbuddy    # 残留报告（只读）
python cli.py cleanup --agent workbuddy --dry-run
python cli.py cleanup --agent workbuddy --dispositions safe
python cli.py uninstall --agent workbuddy --preflight-only
python cli.py uninstall --agent workbuddy --yes      # 调用官方卸载器（不可逆）
python cli.py verify --agent workbuddy     # 卸载后验证
python cli.py admin-cleanup --agent workbuddy             # 需提权的清单（不弹 UAC）
python cli.py admin-cleanup --agent workbuddy --show-script
python cli.py admin-cleanup --agent workbuddy --yes       # 弹一次 UAC
python cli.py quarantine                   # 隔离区与保留策略
python cli.py restore --op-id <id>         # 还原
```

退出码：`0` 成功，`1` 出错，`2` 被安全检查拒绝。

## 第四部分：边界（不声称「一定卸载干净」）

| 不处理 | 原因 |
|---|---|
| 程序安装目录 | 交给官方卸载器；手工删会留下更多注册表残渣 |
| 卸载注册表项本身 | **尚未实现**。卸载器通常自己删，残留时本工具清不掉 |
| 凭据管理器（`cmdkey`） | **尚未实现扫描** |
| 环境变量 `PATH` 条目 | **尚未实现扫描** |
| `App Paths` / 文件关联 / 协议处理器 | **尚未实现扫描** |
| 系统服务与计划任务 | 只报告不删：误删可能影响系统 |
| GUID 命名的厂商键 | 已检测到但**无法归属**到具体 Agent（名字是裸 GUID），不会进任何清理方案 |
